Phase 01 ✓ Complete
GPU Cluster Simulation Engine
Built discrete-time event simulator from scratch modelling realistic 8-node, 32-GPU cluster. Features: FIFO baseline scheduler, greedy GPU allocation, full cluster state tracking including node heterogeneity, queue depth, and GPU fragmentation metrics. Simulation time configurable (default 300 timesteps). Foundation for all downstream components.

Phase 04 ✓ Complete (Issue Found)
Wait-Time Regression: Feature Leakage Discovery
Transitioned to continuous XGBoost Regressor for wait-time prediction. Initial results: MAE 5.25 ts, R² 0.833. Critical issue identified: feature smaller_jobs_in_queue contributed 82% of importance — essentially encoding FIFO queue rank directly. At inference (proactive reordering), this feature becomes meaningless or misleading.
XGBoost Regressor train_wait_model.py Feature leakage detected ⚠ Action required
Critical Issue: Data leakage via dominant feature encoding queue position. In FIFO scheduler, this feature reflects job arrival order. When queue is reordered (Phase 05+), the feature becomes invalid for new job arrivals — creates harmful model bias at inference time.
Phase 05 ✓ Complete (Fix Implemented)
Feature Leakage Fix & Model v2 Retraining
Replaced leaky features with 6 principled cluster-state signals valid at any scheduling policy: (1) can_fit_now, (2) gpu_fit_ratio, (3) fragmentation, (4) queue_pressure, (5) node_availability, (6) avg_free_per_node. Retrained on clean 2,200-sample dataset with 12 total features. No single feature dominates; top 4 contribute 15–23% each. Model now learns genuine cluster dynamics.

What the fix actually bought: removing the leaky smaller_jobs_in_queue feature did not inflate accuracy — it removed a fake signal. The clean v2 model scores R² 0.837 / MAE 4.69 ts on a proper 20% holdout (5-fold CV MAE 4.74 ± 0.42). An earlier headline of R² ≈ 0.96 was an in-sample artifact of a split-after-fit bug and was retired as dishonest in the July 2026 audit. The value of v2 is a model that learns genuine cluster state and stays valid once the queue is reordered, which the leaky model could not.

Phase 11 ✓ Complete
Sensitivity Analysis (Out-of-Distribution Conditions)
Measured model robustness without retraining under deployment shifts — node counts, runtime distributions, and arrival patterns. Across 72 shifted scenarios (real model evaluated on real shifted simulations): mean R² −0.31 (range −2.32 to +0.85), scheduling improvement ranging −14% to +50%, mean failure rate ≈ 32%. Honest conclusion: retrain per regime and fall back to FIFO when predictions degrade — the model does not generalise out-of-distribution.

Phase 13 ✓ Complete
Fairness & Starvation Prevention Analysis
Implemented comprehensive fairness metrics: maximum wait time, Gini coefficient (inequality), completion-time analysis by job size, starvation count (jobs waiting >threshold). Honest finding over 20 runs: plain proactive reordering worsens tail latency (mean max-wait 57.9 → 124.8 ts) and Gini (0.526 → 0.796) versus FIFO — the mean-wait gain (18.58 → 16.54 ts) is bought at a fairness cost. The anti-starvation bumping variant recovers some tail (max-wait 87.2 ts, Gini 0.688) but raises starved-job count (18.2 → 30.2) and lowers SLA compliance (0.933 FIFO / 0.945 proactive / 0.863 anti-starvation). Run-level Jain fairness is 0.918 vs 0.922 — essentially unchanged.

Key Findings & Insights
Feature Leakage, Honestly Handled: Phase 04 identified data leakage (smaller_jobs_in_queue at 82% importance). Phase 05 replaced it with 12 principled cluster-state signals. This did not inflate accuracy — it removed a fake signal. The clean model scores R² 0.837 / MAE 4.69 ts on a 20% holdout (5-fold CV MAE 4.74 ± 0.42; tuned 4.57 / 0.850). A previously reported R² ≈ 0.96 was an in-sample artifact of a split-after-fit bug and was retired as dishonest in the July 2026 audit. The value is a model that stays valid once the queue is reordered.
Statistical Significance: the 40-run paired benchmark (Phase 09) confirms a 7.71% mean wait-time reduction (± 8.87%) with paired t-test p = 1.4e-06 and Wilcoxon p = 7.1e-06; bootstrap 95% CI [4.95%, 10.34%], 33/40 runs positive. The effect on the mean is small but real and reproducible.
Fairness Trade-off (not preserved): the mean-wait gain comes at a cost. Versus FIFO, plain proactive reordering more than doubles tail latency (mean max-wait 57.9 → 124.8 ts) and worsens the Gini coefficient of waits (0.526 → 0.796). GPU utilisation is unchanged (≈64%). The anti-starvation variant trims the tail (87.2 ts, Gini 0.688) but raises the starved-job count (18.2 → 30.2) and lowers SLA compliance to 0.863; the tail-latency cost must be weighed against the mean improvement.
Real-trace gap (Phase 25 open): the only trace on disk is a synthetic proxy (synthetic_proxy_trace); against it the model transfers poorly (R² ≈ 0.015, MAE ≈ 15 ts). OOD sensitivity (72 scenarios) gives mean R² −0.31 with ≈ 32% failure rate. The pipeline is a solid simulation-based study; it is not yet validated on production workloads — retrain per regime with a FIFO fallback.
Complete & Reproducible Study: the 30-phase pipeline includes OOD sensitivity analysis, online learning, concept drift detection, scaling studies, proxy-trace evaluation, and a one-command reproducibility kit (12/12 steps green after the July 2026 audit, which fixed 37 verified defects). It is a thorough simulation-based investigation; the real-trace and fairness results above mark the honest boundaries of what can be claimed before production validation.
