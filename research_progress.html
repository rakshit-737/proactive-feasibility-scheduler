Research Journey
Phase 01
GPU Cluster Simulation
Built a discrete-time event simulator from scratch modelling a realistic 8-node, 32-GPU cluster with FIFO scheduling, greedy GPU allocation, and full cluster state tracking at every timestep.
minimal_gpu_cluster.py dataset_minimal_gpu_cluster.py 8 nodes × 4 GPUs SIM_TIME = 300
Phase 02
Dataset Generation & Feature Engineering
Ran 20 independent simulations to generate 2,200 diverse training samples. Feature snapshots captured at each job's arrival moment. Pivoted from binary classification to continuous wait-time regression.
generate_large_dataset.py 2,200 samples 20 simulation runs wait_dataset.csv
Phase 03
Model Training — Baseline Classifiers
Compared Logistic Regression, Random Forest, and XGBoost on the feasibility classification task (ROC-AUC ~0.93 for XGBoost). Project then pivoted to regression for a richer, rankable scheduling signal.
Logistic Regression Random Forest XGBoost Classifier train_model_withxg.py
Phase 04
Wait-Time Regression Model
Extended to continuous wait-time regression using XGBoost Regressor. Original model (MAE 5.25 ts, R² 0.833) revealed a near-leakage issue: smaller_jobs_in_queue contributed 82% of feature importance — essentially encoding FIFO queue rank directly.
XGBoost Regressor train_wait_model.py wait_model.pkl feature_importance.png
Problem identified: smaller_jobs_in_queue at 0.82 importance = near data leakage. In a FIFO scheduler this feature encodes queue position directly. At inference time (proactive ordering), the queue is reordered so this feature becomes meaningless — or actively misleading.
Phase 05 — ✓ Complete
Feature Leakage Fix & Model v2
Replaced leaky features with 6 principled cluster-state signals that are valid at any scheduling policy. Retrained on clean 2,200-sample dataset (12 features total). No dominant feature — top 4 each contribute 15–23% importance. Model now learns genuine cluster dynamics.
can_fit_now gpu_fit_ratio fragmentation queue_pressure node_availability avg_free_per_node
Original (with leakage)

Significant improvement: Removing the leaky feature and replacing with principled cluster-state features improved R² from 0.833 → 0.937 and MAE from 5.25 → 2.87 timesteps. The model now learns genuine cluster dynamics, not queue position.
Phase 06 — ✓ Complete
Proactive Scheduler Benchmark
Updated proactive scheduler to load wait_model_v2.pkl with the correct 12-feature schema. Fixed a critical dispatching bug: the original implementation dispatched only one job per tick (via break), artificially throttling throughput vs the FIFO baseline. With both schedulers dispatching all fitting jobs per tick — differing only in queue order — the proactive scheduler achieves consistent wait-time reductions.
proactive_Schedule_v2.py wait_model_v2.pkl benchmark_and_plot.py 10-run benchmark

Result: Pilot benchmark shows 10.4% wait-time reduction (std 11.5%) over 10 independent runs, with identical GPU utilisation to FIFO. The improvement is purely from smarter queue ordering — the model guides which job to serve next, not how many. The larger 40-run benchmark in Phase 09 reports a more conservative but statistically significant 7.5% mean improvement. Result plots saved to 05_results/.
