Phase 01 ✓ Complete
GPU Cluster Simulation Engine
Built discrete-time event simulator from scratch modelling realistic 8-node, 32-GPU cluster. Features: FIFO baseline scheduler, greedy GPU allocation, full cluster state tracking including node heterogeneity, queue depth, and GPU fragmentation metrics. Simulation time configurable (default 300 timesteps). Foundation for all downstream components.

Phase 04 ✓ Complete (Issue Found)
Wait-Time Regression: Feature Leakage Discovery
Transitioned to continuous XGBoost Regressor for wait-time prediction. Initial results: MAE 5.25 ts, R² 0.833. Critical issue identified: feature smaller_jobs_in_queue contributed 82% of importance — essentially encoding FIFO queue rank directly. At inference (proactive reordering), this feature becomes meaningless or misleading.
XGBoost Regressor train_wait_model.py Feature leakage detected ⚠ Action required
Critical Issue: Data leakage via dominant feature encoding queue position. In FIFO scheduler, this feature reflects job arrival order. When queue is reordered (Phase 05+), the feature becomes invalid for new job arrivals — creates harmful model bias at inference time.
Phase 05 ✓ Complete (Fix Implemented)
Feature Leakage Fix & Model v2 Retraining
Replaced leaky features with 6 principled cluster-state signals valid at any scheduling policy: (1) can_fit_now, (2) gpu_fit_ratio, (3) fragmentation, (4) queue_pressure, (5) node_availability, (6) avg_free_per_node. Retrained on clean 2,200-sample dataset with 12 total features. No single feature dominates; top 4 contribute 15–23% each. Model now learns genuine cluster dynamics.

What the fix actually bought: removing the leaky smaller_jobs_in_queue feature did not inflate accuracy — it removed a fake signal. The clean v2 model scores R² 0.83 / MAE 5.35 on a proper 20% holdout (in-sample 0.96 / 2.56). The value is a model that learns genuine cluster state and stays valid once the queue is reordered, which the leaky model could not.

Phase 09 ✓ Complete
40-Run Statistical Benchmark (Conservative Validation)
Conducted large-scale 40 paired-seed benchmark to establish statistical significance. Both FIFO and proactive schedulers tested with identical random number sequences. Phase 13 ✓ Complete
Fairness & Starvation Prevention Analysis
Implemented comprehensive fairness metrics: maximum wait time, Gini coefficient (inequality), completion-time analysis by job size, starvation count (jobs waiting >threshold). Added an optional starvation-prevention bumping variant. Honest finding: plain proactive reordering worsens tail latency (mean max-wait ~58→128 ts) and Gini (0.51→0.79) versus FIFO — the mean-wait gain is bought at a fairness cost. The bumping variant exists specifically to mitigate this.

Key Findings & Insights
Feature Leakage, Honestly Handled: Phase 04 identified data leakage (smaller_jobs_in_queue at 82% importance). Phase 05 replaced it with 12 principled cluster-state signals. This did not inflate accuracy — it removed a fake signal. The clean model scores R² 0.83 / MAE 5.35 on a 20% holdout (5-fold CV MAE 5.68 ± 0.71); the value is a model that stays valid once the queue is reordered.
Statistical Significance: 40-run paired benchmark (Phase 09) confirms 7.5% mean wait-time reduction (± 9.0%) with paired t-test p-value 1.10e-06 (highly significant). The effect on the mean is small but real and reproducible.
Fairness Trade-off (not preserved): the mean-wait gain comes at a cost. Versus FIFO, plain proactive reordering more than doubles tail latency (mean max-wait ~58→128 ts) and worsens the Gini coefficient of waits (0.51→0.79). GPU utilisation is unchanged (64.1%). A deployment would need the anti-starvation variant, and the tail-latency cost must be weighed against the mean improvement.
Real-trace gap: the synthetic-trained model does not transfer to the LANL trace (cross-dataset R² ≈ −0.02). The pipeline is a solid simulation-based study; it is not yet validated on production workloads.
Complete & Reproducible Study: the 21-phase pipeline includes OOD sensitivity analysis, online learning, concept drift detection, scaling studies, real-trace evaluation, and a one-command reproducibility kit. It is a thorough simulation-based investigation; the real-trace and fairness results above mark the honest boundaries of what can be claimed before production validation.
