Project Overview

The Full Research Arc

From problem statement to 21-phase research pipeline with publication-ready results.

Modern GPU clusters in HPC (High-Performance Computing) environments typically schedule jobs using FIFO (First-In, First-Out) — the simplest possible policy. A job joins the queue, waits its turn, and is dispatched when enough GPUs are free. This works, but it ignores everything the cluster knows: fragmentation, competing jobs, job sizes, and whether the cluster is trending toward idle or contention.

This project builds a proactive scheduler: one that uses a trained machine learning model to predict how long each queued job will actually wait, then reorders the queue so jobs that can be served quickly are served first. The entire system is built on a custom discrete-time cluster simulator written from scratch — no external HPC frameworks, just Python. The research spans 21 phases: from simulation and dataset generation through feature engineering, multi-model comparison, fairness analysis, SHAP explainability, real-trace validation, scaling studies, online learning, concept drift, ROI analysis, and reproducibility.

"The goal is not to break fairness — it is to make smarter decisions about which job to attempt next, using cluster state as a signal."

System Architecture

Three interlocking components: a simulator that generates labelled training data, a model that learns to predict wait time from cluster state, and a scheduler that uses that model at inference time to prioritise the queue. All three share the same 12-feature cluster-state schema, ensuring consistency and avoiding data leakage.

Methodology & Phases

21-Phase Research Pipeline

Complete arc from simulation to publication-ready reproducibility.

Phases 01–05: Core pipeline (simulation, dataset, baseline models, regression, proactive scheduler)

Phases 06–09: Model analysis (classifiers, load profiles, 40-run benchmark, hyperparameter tuning)

Phases 10–13: Robustness & explainability (sensitivity analysis, ablation study, fairness, SHAP)

Phases 14–21: Advanced analysis (real traces, scaling, online learning, concept drift, ROI, reproducibility, interactive tools)

Phase 04 Challenge: Feature Leakage

Initial regression (Phase 04) revealed a critical issue: the feature smaller_jobs_in_queue dominated feature importance (82%), essentially encoding FIFO queue rank. At inference time, the queue is reordered, making this feature meaningless or actively misleading. Phase 05 Fix: Replaced leaky features with 6 principled cluster-state signals valid at any scheduling policy. Result: R² improved 0.833 → 0.937, MAE improved 5.25 → 2.87 ts. No single feature dominates; top 4 each contribute 15–23%.

Core Phases (01–05)

Phase 01: Cluster Simulation. Discrete-time event simulator modelling 8-node, 32-GPU heterogeneous cluster with FIFO baseline, greedy GPU allocation, and full state tracking.
Phase 02: Dataset Generation. 20 independent runs → 2,200 diverse training samples. Feature snapshots captured at job arrival.
Phase 03: Classifier Comparison. Logistic Regression, Random Forest, XGBoost on binary feasibility (ROC-AUC ~0.93 for XGBoost).
Phase 04: Wait-Time Regression. Extended to continuous regression. Original model MAE 5.25, R² 0.833 — but exposed feature leakage issue.
Phase 05: Proactive Scheduler Benchmark. Fixed feature leakage, retrained model v2 (12 principled features). Scheduler loads v2 model and reorders queue. Paired 10-run benchmark: 10.4% avg wait reduction.

Analysis Phases (06–09)

Phase 06: Multi-Model Regression. Benchmarked 7 algorithms (Linear, RF, LightGBM, CatBoost, MLP, XGBoost, Ensemble) on improved_wait_dataset.csv. Exported thesis Table 1 metrics.
Phase 07: Load-Profile Expansion. Generated low/high/bursty datasets (2,200 samples each) and evaluated XGBoost on each profile separately.
Phase 08: 40-Run Statistical Benchmark. Paired t-test on 40 seeds for FIFO vs proactive. Result: 7.5% mean improvement, p-value 1.10e-06 (highly significant).
Phase 09: Hyperparameter Tuning. GridSearchCV over 243 configurations. Best depth=4, lr=0.01, n=500. Marginal R² improvement (+0.0096) vs baseline; MAE slightly worse (+0.0366).

Robustness & Explainability Phases (10–13)

Phase 10: Sensitivity Analysis (OOD). Measured model robustness under node-count shifts (6/10/12), runtime distributions, and arrival patterns. Some OOD settings show negative R²; informs deployment guardrails.
Phase 11: Ablation Study. Systematic 12-feature ablation with R² drop ranking. Top features: can_fit_now, gpu_fit_ratio, fragmentation, queue_pressure.
Phase 12: Fairness & Starvation Analysis. Added fairness metrics (max wait, Gini, starvation count) and bumping policy. Proactive scheduler shows 65% fewer starvation events.
Phase 13: SHAP Explainability. Generated summary, dependence, and force plots explaining model decisions. Validated feature interpretability.

Advanced Analysis Phases (14–21)

Phase 14: Real-Trace Validation. Parsed LANL-format workloads. Evaluated cross-dataset performance and domain transfer.
Phase 15: Scaling Study. Evaluated 4/8/16/32-node cluster sizes (8/32/128/256 GPUs). Overhead and inference time analysis.
Phase 16: Online Learning. Incremental model updates on streaming data using mini-batch retraining.
Phase 17: Concept Drift Detection. Rolling MAE trigger for adaptive retraining. Validates stability over time.
Phase 18: ROI Analysis. GPU-hour savings, energy savings, annual cost-benefit (3–5 year payoff depending on cluster size).
Phase 19: Reproducibility Kit. One-command pipeline (run_all_experiments.sh), Docker container, requirements.txt, comprehensive README.
Phase 20: Interactive Dashboard. dashboard.py provides real-time visualisation of scheduler decisions and performance metrics.
Phase 21: Publication Pipeline. Integrated tables, plots, and results into project_report.html and research_progress.html. GitHub Pages docs/ with interactive explorer. Ready for submission to HPC venues (SC, PPoPP, SIGMETRICS).

Feature Set Rationale

Each feature is computed from observable cluster state at job arrival time and remains valid regardless of scheduling policy. Features span four categories: (1) Allocation feasibility: can_fit_now, gpu_fit_ratio. (2) Fragmentation signals: fragmentation, node_availability. (3) Queue dynamics: queue_pressure, avg_free_per_node. (4) Job & cluster profile: job_size, cluster_load, plus 4 additional derived metrics. No single feature exceeds 21% importance.
